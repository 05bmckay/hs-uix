# v2.3.0

## Changes
- Numeric column `width` values now actually work. HubSpot's `TableHeader`/`TableCell` silently ignore numeric widths, so `width: 160` previously fell back to content sizing. DataTable now renders the header label inside an `AutoGrid` with that fixed `columnWidth`, giving the table real content of that width to measure — which sets the minimum width for the whole column, in display and edit mode alike.
- Auto-width now gives editable date/time columns fixed pixel header widths (`date` 160, `time` 130, `datetime` 300). Previously these columns were sized by content, and an empty `DateInput`/`TimeInput` gave the table almost nothing to measure — in a crowded table, clicking into edit mode collapsed the input to icon-only width. A numeric header width reserves predictable column space instead; override with a manual `width` on the column as usual.
- `showClearFiltersButton` now defaults to the value of `showFilterBadges` (was always `true`). Setting `showFilterBadges={false}` now hides the "Clear all" reset button by default too; pass `showClearFiltersButton={true}` to keep the reset without chips. Behavior is unchanged when `showFilterBadges` is left at its `true` default. ([#10](https://github.com/05bmckay/hs-uix/issues/10))
- The record count now sits on the title row when a `title` is set and the toolbar has no left-hand content (search and filters hidden), instead of always rendering in the toolbar's right column. A count-only header now sits on one line instead of stacking; the count still rides in the toolbar whenever search/filter controls are present.
